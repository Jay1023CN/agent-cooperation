# Claude 桌面会话交接验证（2026-10-28）

本次对象是 Windows 上已经打开的 Claude Code 桌面会话「Agent Cooperation 项目审查与优化」，没有新建 Claude 模型会话。

## 实际走通的部分

Codex 通过 `agent_link.desktop_handoff --role host` 发布 UI 协作文档请求并保持租约。原 Claude 会话用 MCP stdio 客户端连接 `desktop` 端，调用领取和提交工具。宿主读到了 `submitted` 记录，以及 Claude 整理的 UI 现状、改进顺序、后端接口建议和文件证据。交接标识为 `codex-claude-design-handoff-20261028`。

这验证了真实桌面会话中的文档领取与回传。没有验证多机执行、代码独立验收、自动唤醒或持续无人值守运行。

## 连接方式与本次发现

新增的项目 `.mcp.json` 没有被旧会话自动加载。第一次接入通知及后续领取通知通过桌面输入控件发送，属于临时界面操作；文档内容和返回结果通过 MCP 交接。因此本次不能称为无需界面操作的全自动双向连接，也不能称为旧会话原生加载了新连接器。

Windows MSIX 应用可能重定向 `%LOCALAPPDATA%` 下的文件。双方最初看到不同数据库，Claude 排查后找到宿主实际写入的库并完成交接。随后把数据库通过 SQLite 备份 API 复制到双方都能访问的项目缓存目录，更新了本机 MCP 配置；旧记录保留。实际部署应使用双方明确共享的绝对文件路径，不仅比较环境变量展开后的字符串。

Claude 曾反馈命令输出中的中文出现替换字符。宿主核对数据库和交接脚本，原始中文均完整；这次没有发现已保存的交接说明损坏。本机配置仍显式启用了 Python UTF-8 模式，避免终端编码影响显示和后续集成。

## 复用现有 Pal

本次代码为 `agentlink` 加入了 `handoff_list`、`handoff_claim`、`handoff_status`、`handoff_submit`，直接复用同一数据库和租约规则。已有 Pal 连接重新连接后可加载新工具定义，操作见[桌面交接说明](desktop-handoff.md)。该入口已通过本地契约测试；本次没有继续消耗 Claude 额度验证它在桌面中的原生调用。

当前仍需要会话主动调用交接工具。Pal 已连接不代表外部代理可以向任意现有会话发送消息；自动唤醒尚未实现。
