# PAL Arena 产品规格

## 已确认的使用目标

用户与 partner 共同参加比赛，使用自己的四台电脑和各代理订阅，在一个网页中完成需求沟通、任务拆解、研究、文档、开发、调试、网页和 Blender 产物制作。平台暂名 PAL Arena，业务代码位于 `arena/`，复用本仓库的 PAL Agent Link 连接能力。Multica 的现有能力作为架构参考；本模块不复制其界面代码。

机器：常开的 Mac mini（24GB 内存、512GB 磁盘）、一台 Neo、天选 6 Pro、天选 7 Pro Max。全部以已有桌面软件为起点，平台同时提供新任务会话与已有会话的适配入口。Mac mini 没有公网 IP，远程访问默认使用 Tailscale Serve 和同一 tailnet。5GB 为中心暂存预算，大视频不在当前主要场景内。

## 最终体验

1. 两名成员使用各自的登录令牌进入同一工作区。共享主对话讨论项目；个人对话可先与负责人完善想法，再把决定发到共享对话。
2. 创建项目，填写比赛目标、GitHub 仓库及验收清单。主对话保持需求版本，负责人通过平台工具创建执行任务，指定能力、依赖和交付要求。
3. 四台电脑主动连接中心并上报实际配置的 agent。调度器先检查角色、能力、实际接入状态、并发、上下文和代码可达性，再按照难度、质量/经济性偏好及有限的执行记录选择成员。每次派发记录原因。订阅额度仍由客户端控制，未知余额明确显示为未知。
4. Agent 在自己电脑上执行。代码任务使用独立工作目录和分支，任务之间通过已完成的提交交接。每次运行保留结果、会话信息、分支/提交、日志和实际产物引用。
5. 完成执行后安排不同成员独立验收；没有结构化结论和验证证据不能判定通过。失败退回修订，最多自动修订到三次执行，随后显式等待处理。
6. 所有执行任务验收完成后唤醒负责人汇总。最终项目交付必须匹配当前需求版本。执行子进程退出和项目完成是不同状态。
7. 项目里查看任务看板、实时追加日志、验收记录、机器列表、使用统计、文件差异摘要和产物列表。真实机器未连接时显示空状态，不把演示数据显示成在线资源。
8. 项目记忆和个人偏好分别管理。负责人从成员对话自动整理长期记忆，成员可查看、修改和删除；运行使用带来源及版本的快照。

界面默认跟随系统切换浅色和深色，字体、字号、间距及组件均使用统一规范。前端源码独立放在 `frontend/`，可单独预览和构建；Python 服务只提供 API 并分发构建后的静态文件。修改界面不需要修改调度器或数据库。

## 对话和协作边界

个人对话的消息、任务、运行日志及产物仅向当前成员开放；共享项目任务向两名成员开放。个人对话 agent 不能修改共享需求或确认共享项目交付。希望团队执行的决定应发送到共享主对话。任务里的回复采用公开结果，不读取或展示模型内部思维。

负责人可以委派，执行成员也可以请求子任务帮助。委派中的执行任务等待全部子任务独立验收后继续整合，不能在子任务未完成时提前验收自己。依赖任务要等前置任务通过验收才能启动。

已知的执行阻塞会生成一次负责人处理任务；受限恢复工具最多安排三次执行。断线或外部操作结果未知时，不自动创建替代任务重复执行。取消指令会撤销该任务与受影响子任务的回写权限；取消汇总或恢复任务后不会立即重新生成同一份工作。

## 接入方式的现实边界

- Antigravity：沿用 PAL 的桌面本地 RPC。支持新建会话；显式提供会话 ID、模型和对应本地工作目录时可使用已有会话。
- Qoder / Qoder CN：现有 PAL 用 ACP 新会话；不声称接管 IDE 中现有聊天。其 CLI 与账户可用性需要本机检查。
- WorkBuddy：官方本地助理 Open API 不能可靠确认任务终态，只适合人工监督。Arena 另有桌面 MCP 原型，由已登录的桌面会话主动领取共享任务并明确提交结果；该桥尚未接入 Multica，真实客户端与订阅仍待实机验证。
- OpenCode：沿用 PAL 本机 HTTP 适配器。
- Codex / Claude / Gemini：提供可选的官方 CLI 执行入口，使用各自登录态。桌面版安装不代表 CLI 已安装或共享同一会话。当前不提供通用桌面点击接管。
- GLM：是模型选择，需由实际使用它的客户端承载，不能作为一个凭空可执行的本机程序。
- Blender：由具备 Blender 命令/脚本能力的本机 agent 执行，并生成可打开的文件。平台本身不等同于建模引擎；需要按用户实际安装位置配置。

平台不会模拟上述未连接功能的成功状态。端到端实机验收需要四台电脑连接、客户端登录、可用模型，以及真实 GitHub 凭据。

## 存储与运行

中心服务使用 SQLite 和本地文件，默认端口 8765，只监听 127.0.0.1。文件上限默认 5,000,000,000 字节，单次产物上传上限 128MiB。新上传文件默认保护，只有解除保护的历史产物才进入清理范围。代码 Git 历史保存在 GitHub，执行机工作副本另外计量。

5GB 是可配置的暂存预算，不是操作系统、代理缓存、GitHub 容量或四台电脑所有磁盘的硬限制。数据库写入不是文件系统硬配额。运行中的工作目录、未同步提交及结果未知的现场必须保留。后台日志有数量和单条大小限制，防止无限累积。

网络断线导致执行状态不明时暂停回写，禁止自动重复提交同一写任务。中心服务不自动分配到另一台机器重跑未知状态工作。任务令牌限定当前运行，取消或过期后不能继续完成任务。

模型使用受限的任务操作令牌；执行端另外持有心跳和完成确认令牌。验收结果只有在执行端核对提交和输入产物后才能完成，服务端再次检查验收提交与原成果相同。

具体设置见 [模型分配、记忆与代码交接](arena-routing-memory.md)；备份与服务管理见 [维护与恢复](arena-maintenance.md)。

## 发布策略

项目可开启 GitHub 工作分支推送，并可选择自动合并和/或部署。发布任务只分配给配置了同名本地 release profile 的在线执行器：整合当前需求版本已独立验收的提交，运行指定检查，再执行非强制推送与部署命令。未配置或未上线时保持排队，不显示为已发布；结果不确定时停止自动重试。比赛提交由两名成员完成。
