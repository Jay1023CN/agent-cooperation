# 跨电脑任务占用记录（开发中）

这是给桌面任务交接使用的单一登记点，不创建或调度 Multica 任务。每台电脑在创建本地交接前，先为工作区中的任务来源登记占用；同一来源由其他机器或其他本地数据库重复登记时会被拒绝。宿主在登记之前和之后都会重新查询 Multica，再创建本地交接。

中心只应运行一份服务并使用同一个持久数据库。登记永不因超时自动释放：断线、响应丢失、取消和宿主重启都需要检查现场。当前没有自动清理或授权恢复接口；不要直接修改数据库或把旧数据库副本当成新的中心运行。备份和恢复必须连同中心身份、所有未完成任务及各机工作目录一起核对。

## 安装与配置

服务端需要 `python -m pip install '.[platform]'`。准备一个仅运行用户可读的配置文件，格式如下；每台机器使用独立、随机且足够长的 token，工作区 ID 使用 Multica 的实际 ID：

```json
{
  "machine-a": {"token": "替换为独立随机字符串，至少32个字符", "workspaces": ["替换为工作区ID"]},
  "machine-b": {"token": "替换为另一个独立随机字符串，至少32个字符", "workspaces": ["替换为工作区ID"]}
}
```

可以用 `python -c "import secrets; print(secrets.token_urlsafe(32))"` 为每台机器单独生成 token。不要提交配置文件、打印 token 到日志或把 token 发给其他机器。

```text
python -m agent_link.coordination --db <中心数据库绝对路径> --config <机器配置绝对路径> --port 8781
```

服务固定监听 `127.0.0.1`。其他电脑必须通过经身份和权限配置的私有 HTTPS 代理连接，代理、TLS 和各机身份仍需真实环境验证。不要把无加密 HTTP 直接暴露到网络。服务不提供任务内容或 Multica 令牌。

各执行电脑的 host MCP 在原有 `--multica-task` 参数后增加 `--coordinator-url <中心HTTPS地址>`；在本机的 MCP 环境中设置该机器专属的 `COOPERATION_COORDINATION_TOKEN`。本地交接数据库包含随机实例 ID，中心用它区分工作区；不要在不同安装之间复制该数据库。每个 MCP 客户端必须指向同一套中心配置，并在自己的电脑上使用同一份本地交接数据库，否则不能保证去重。

同时启用 Multica 校验和中心登记时，宿主进程每 15 秒自动核对 Multica 运行状态与中心记录，再为本地任务续期。任一核对失败就停止续期并将任务标为过期；如果无法写入数据库，已有期限到达时同样会过期。桌面会话仍须主动查询状态并停止，服务无法远程强制终止它。该后台续期依赖宿主 MCP 进程持续运行，不会重新启动已过期任务。

中心请求返回失败或结果不明时，使用 host MCP 的 `inspect_coordinator` 查看登记所属机器与任务；该查询不代表原会话已停止，也不授予重试。Multica 状态和重试关系核验只能覆盖接口明确返回的数据，当前仍有其他派生任务和读取后状态变化的竞态。当前方案仅通过本机模拟 HTTP 和并发测试，真实多机、代理与异常恢复尚未验收。
